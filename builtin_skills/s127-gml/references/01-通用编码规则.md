# 通用编码规则（基类属性）

对应《S-127数据生产与发布操作指南（修订版）》第 4 章、5.1 节。
所有要素类都继承这些属性，规则只在这里写一遍。

---

## 0. 取值未知时填什么（DCEG 2.4）

S-127 产品规范附录 A（DCEG）§2.4「Missing attribute values」定下两条硬规则，
**必填与非必填的处理方式相反**，写反了就是错的：

| 属性 | 取值未知时 | 要素清单里怎么写 |
|---|---|---|
| **必填**（要素目录 lower≥1） | **必须**写成空（null）值，不能省略 | `"attr": {"$nil": true}` |
| **非必填**（lower=0） | **不得**出现在数据集里 | 整个键不要写 |

> Where a value of a mandatory attribute is not known, the attribute must be
> populated with an empty (null) value.
> Where the value of a non-mandatory attribute is not known, the attribute must
> not be included in the dataset.

`{"$nil": true}` 会输出成 `<attr xsi:nil="true"/>`；枚举属性另按生产惯例补
`code="unknown"`。必填属性取值未确定时按缺值规则处理，必要时报告待核对。

这解释了一个常见误判：**空元素不是缺陷**，省略必填属性才是。哪些属性必填见
`02-要素字典.md` §二，或跑 `python3 $S/lookup_schema.py attrs <要素类>` 看 ★ 标记。

## 1. language 语言

- S-127 数据集**默认语言为英文**。所有非枚举类属性约定**先英文、后中文**，中英内容保持一致。
- 复合属性中的 `language` 子属性填 **ISO 639-3**：英文 `eng`，中文 `zho`。
- **例外 —— ContactDetails**：其简单属性 `language` 表达「联系该机构时使用的语言」，
  只填一种。该要素的所有非枚举属性只用这一种语言填写。
  机构支持中英双语服务时，**分别创建两个 ContactDetails**（一个 eng、一个 zho）。
- 资料来源字段另按第 4 节执行：中文来源的 `sourceIndication.source` 先英文、后中文；`sourceIndication.countryName` 仅填国家英文名称。这两项不套用 ContactDetails 的单语约定，`countryName` 也不套用通用双语约定。
- 属性不具备多重性时（如 `contactInstructions`），中英双语填进同一格。

### 在要素清单 JSON 里怎么写

| 情形 | 写法 | 生成结果 |
|---|---|---|
| 单值文本属性 | `"source": ["Notice No.4/2021", "2021年第4号通告"]` | 一个元素，英文 + CR + 中文 |
| 名称 | `"featureName": {"eng": "...", "zho": "..."}` | 两个 `featureName` 元素 |
| 文本内容 | `"text": {"eng": "...", "zho": "..."}` | 两个 `information` 元素 |
| ContactDetails | `"attributes": {"language": "eng"}` + 属性只写英文 | 单语要素 |

脚本会把 CR 正确转义成 `&#13;`（真实数据集就是这样分隔双语的）。

## 2. fixedDateRange 数据有效时间

`dateStart` 表示经核对的生效日。`dateEnd` 采用交付方明确要求的最后有效日或届满界点；在 `validityBasis` 记录出处和口径。缺少日期依据时留空。

| 原文 | dateStart | dateEnd |
|---|---|---|
| 自2024年4月7日起执行，有效期至2029年4月6日 | 2024-04-07 | 2029-04-06 |
| 自2010年7月1日起施行 | 2010-07-01 | （不填） |
| 自2024年9月7日起施行，有效期五年 | 2024-09-07 | 2029-09-06 |

原文只给整数年数时，核实生效日和周年届满界点。届满前一日为最后有效日，记录表用该日；GML 按交付口径选择。周年或明示截止日期有歧义时列为待核对。JSON 里用 `YYYY-MM-DD`，脚本负责包 `<s100:date>`。

## 3. featureName 要素名称

### 专属 vs 可复用

| | sourceIndication | 典型要素 |
|---|---|---|
| **专属要素** | 必填 | 所有地理要素、Regulations、Restrictions、ShipReport |
| **可复用要素** | 不填（便于不同来源要素重复关联） | Authority、ContactDetails、ServiceHours、Applicability、NonStandardWorkingDay |

例外：ContactDetails 的信息来自多份文件时，允许填多个 `sourceIndication`。

### displayName 约定

| 要素 | 英文 featureName | 中文 featureName |
|---|---|---|
| APPLIC（Applicability） | 不选 | 不选 |
| 其他所有要素 | 不选 | **必选 `true`** |

> 语料里存在偏差（个别 Authority 未填、个别 RouteingMeasure 英文填了 true），
> **以指南规则为准**，脚本按指南规则生成。
> 复合属性里的 `featureName`（如 `sourceIndication/featureName`）`displayName` 一律留空。

### 命名要求

- 词首大写；命名尽量精简，重点体现**所属区域/系统 + 功能**
- 英文名称含数值用千分位：`Chinese-flagged Ships of 2,000 GT and Above`
- **名称使用公告或附件原名**；原名中的所属海域、港口和航路段照录。原文未使用的地名前缀不添加。

命名时先采用原文；无独立名称时，用原文明示的区域、服务或规则用途组合成可追溯的名称。同名但边界、限制或适用对象不同的要素通过来源和范围区分。

### APPLIC 命名的去重与概括（指南 6.1）

适用船舶列表转 APPLIC 时，按实际适用范围、阈值、豁免和逻辑分组去重。只有确认合并后条件等同时才使用概括类别。

来源用国籍、船籍、用途或吨位限定适用船舶时，保留该限定及它的修饰范围。仅在条文明示为补集时处理“其他”类别；不能把前一分支的适用范围扩大到后一分支。

## 4. sourceIndication 资料来源

地理要素 0 或 1 个；信息要素 0 或多个。

| 子属性 | 填法 |
|---|---|
| `categoryOfAuthority` | 发文机构类型；直属海事局及以上 → `maritime` |
| `countryName` | 来源机构所属国家的英文名称。中国统一填写 `China`，仅保留英文，不填写“中国” |
| `reportedDate` | 实际文件发布日期（以原件或可核实的发布记录为准）。无法确认时省略；生效日、系统执行日和数据集生成日都不能代填 |
| `source` | 信息来源名称，可为出版物、文件、参考书籍、指南／说明、船舶等名称。**优先填写文号**，无文号时填写实际来源名称；中文来源须同时填写英文和中文，顺序为先英文、后中文 |
| `sourceType` | 直属海事局及更高级别 → `law or regulation`；地方海事局及同级、航行通告、ENC → `official publication` |
| `featureName` | 发文机构/组织名称，`displayName` 留空，`language` 必填且唯一 |

### source 信息来源名称

填入实际采用的信息来源名称，如出版物、文件、参考书籍、指南／说明、船舶等。

1. **先核对文号。** 从原始公告页、正文或可核实的目录取得实际文号；有文号时优先填写文号，无文号时才填写实际来源名称。
2. **中文来源同时填写英文和中文，先英文、后中文。** 两种语言表达同一来源；保留文号明确包含的年份、编号及文种，原文未提供的信息不得补造。
3. **文号与发文机构分别填写。** 文号中包含的发文机构名称不重复写入 `source`，机构名称填写在 `sourceIndication.featureName.name` 中；机构名称和缩略语按原文或其官方英文名核对，`displayName` 留空。
4. **无文号时保留实际名称。** 采用文件名称时，可删除标题外围的发文机构及“关于发布”“的通告”等发布套语，保留文件的实际名称。
5. **缺失说明另行记录。** 缺文号或日期的说明放在检查报告，不能附加到 `source` 值里。

`source` 是单值文本。要素清单 JSON 中可使用先英文、后中文的数组简写，如 `["Notice No.4/2021", "2021年第4号通告"]`；脚本以 CR 分隔合并到**同一个 `source` 元素**中，不生成两个 `source` 元素。

以下案例中的机构名称仅展示中文部分；机构英文名称按官方英文名核对后填写，双语机构名分别使用带对应 `language` 的 `featureName`。

#### 案例 1：有年份的通告文号

来源文件：福建海事局关于发布《中华人民共和国福建海事局VTS服务指南》的通告。

文号：福建海事局2021年第4号通告。发文机构：福建海事局。

| 字段 | 填写内容 |
|---|---|
| `source`（要素清单 JSON） | `["Notice No.4/2021", "2021年第4号通告"]` |
| `sourceIndication.featureName.name`（中文） | 福建海事局 |
| `countryName` | `China` |

#### 案例 2：未提供年份的公告文号

来源文件：中华人民共和国海事局第16号公告。

| 字段 | 填写内容 |
|---|---|
| `source`（要素清单 JSON） | `["Announcement No.16", "第16号公告"]` |
| `sourceIndication.featureName.name`（中文） | 中华人民共和国海事局 |
| `countryName` | `China` |

### countryName 发文机构的国家名称

填写来源机构所属国家的英文名称。**中国来源仅填写 `China`**，这是通用双语规则的例外；不保留“中国”，也不写成 `China 中国` 或 `["China", "中国"]`。

### 多来源处理

地理要素存在多来源时，唯一的 `sourceIndication` 填「描述该要素地理位置」的那份文件；
其他来源填进 `textContent` 的 `sourceIndication`。

### 地理要素来源的特殊情形（指南 5.1）

以下三种情况，`sourceIndication` **仍然填资料文件**（不是填 ENC）：

1. 文件只给了专有名称、没给几何范围，几何取自 ENC 对应要素
2. 几何由文件描述 + ENC 要素共同构建，或依据示意图勾绘
3. 几何由编辑人员理解勾绘

## 5. textContent 文本内容

- `categoryOfText`：`text` 有内容时**必选**。XSD 只有三个取值：
  `extract`（摘录，最常用）/ `abstract or summary`（摘要）/ `full text`（全文）。
  > 指南 4.5 的行文容易被读成还有个 `information` 取值 —— 那其实是指
  > **子元素** `information`，不是 `categoryOfText` 的枚举值。语料里也只出现
  > `extract` 与 `abstract or summary`。
- `information/text` 用于表达**无法通过枚举属性表达、但对合规航行有重大意义**的内容。
- **仅适用单一地理要素的条文填进该要素的 `textContent`，尽量少建信息要素。**
- 发文机关、可独立关联的规则、报告、适用条件、联络渠道和服务时间按原文及目录判断是否需要独立对象，避免模板预设额外条目。
- **文本逐条保留原文，不得概括、改写或只写摘要。** 超 300 字符时拆成多个 `information`，内容不删；不得把多条要求压缩成一句。
- **条文中描述地理范围的文字一律不作文本属性提取**（如「4号灯塔至14号灯桩之间」「桥区水域」
  「以X为中心、Y半径范围内」等）。地理范围只通过 `geometry` 表达：有明确坐标用 `coords.py`
  换算；无坐标时几何留空、在记录表注明「几何待人工录入」，绝不拿范围文字顶替几何塞进 `text`。

提取限制时同时保留阈值的比较方向、单位和例外。`geometry` 表达地理范围；用于定位的条文可以留在记录表出处或几何待补说明中。

### 长度

S-127 规定 `text` 上限 **300 字符（UTF-8）**。超长时用多个 `information` 拆分表达。
真实数据集中长条文用 CR 分行后每行都在限内 —— 校验脚本按此判定：
单行超 300 判 ERROR，仅总长超 300 判 WARN。

### 条款序号

`text` 中**不标示**原文的条款、段落序号（第X条、X.X.X）。
但《S-127要素生产与检查记录表》必须记录条款来源以便溯源
—— 在要素清单里用 `"clause": "附件1 二（三）"` 记录，它只进记录表、不进 GML。

## 6. 英译（指南 6.6）

英译前先核对本节的“常用固定搭配”；已列术语按固定英文写法使用，其余内容按以下流程处理。

1. 官方发文无英文版时，先**网络搜索英文关键词**，找权威机构的相关英文发文用于参考引用。
2. 用工具英译后**逐句核对**，尽量使用海事、航海专业英语。
3. 中文括号「（）」在英文文本中转成英文括号 `()`。
4. 从 PDF 复制原文会带入多余空格、半拼字符，要清理（指南 6.7）。

### 常用固定搭配

**固定翻译：特大桥 → Grand Bridge。** 要素名称及相关文本中的“特大桥”统一使用该译法，保持用词和大小写一致。

以下两个完整名称为该固定翻译的应用案例：

| 中文名称 | 英文译名（应用案例） |
|---|---|
| 南港特大桥桥区水域 | Nangang Grand Bridge Area Waters |
| 北港特大桥桥区水域 | Beigang Grand Bridge Area Waters |
