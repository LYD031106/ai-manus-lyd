# 专题配方

七类常见专题的成品要素清单。开工先在这里找到对应专题，照抄配方，再按原文调整。
每个配方都标了对应的真实数据集，可作为参照样本。

---

## 1. 定线制和报告制

**参照**：`127CN00ZJK Routeing Measure.gml`（珠江口）；指南 7.1
**命名**：`127CN00<地域>_SRS_VTS001`

### 关键判断

先与最新 ENC 比对：**定线制内容通常已被 ENC 完全覆盖 → 不转换为 S-127 要素**。
只有当定线制文件包含 ENC 未表达的**航行规则条款**时，才按条款作用范围建
`RouteingMeasure`，把条款填进其文本属性或建 `Regulations` 关联。

### 要素配方

| 要素 | 说明 |
|---|---|
`ShipReportingServiceArea` | 报告制覆盖区，填 `requirementsForMaintenanceOfListeningWatch`
`ShipReport` × N | 按 `categoryOfShipReport` 分：航行计划报告 / 终止报告 / 变化报告 / 其他报告（含污染物报告）
`RadioCallingInPoint` × N | 各报告线；`communicationChannel` 填全部可用 VHF；`trafficFlow = two-way`；`componentOf` → SRSA
`Applicability` × N | 各类适用船舶（可复用，不填来源）
`Authority` | 主管机构（可复用）
`ContactDetails` × 2 | 交管中心，eng / zho 各一份
`ServiceHours` | 24小时值班（可复用）

### 关联

```
SRSA --permission(required)--> APPLIC（报告制适用船舶）
SRSA --permission(permitted)--> APPLIC（自愿加入的300总吨以下船舶）
SRSA --reptForTrafficServ--> ShipReport（各类型）
SRSA --consistsOf--> RadioCallingInPoint（自动补 componentOf）
SRSA --controlAuthority--> Authority
SRSA --theContactDetails--> ContactDetails
RadioCallingInPoint --permission(required)--> APPLIC（经过报告线须报告的船舶）
ShipReport --reportTo--> Authority（报告对象机构）
ShipReport --mustBeFiledBy(not required)--> APPLIC（免除报告的船舶）
```

## 2. VTS 服务指南

**参照**：`127CN00NDVTS001.gml`（福建-宁德）；指南 7.2
**命名**：`127CN00<地域>VTS001`

### 要素配方

| 要素 | 说明 |
|---|---|
`VesselTrafficServiceArea`（总区） | 沿海 VTS 分区（如「福建沿海VTS第Ⅰ区」）
`VesselTrafficServiceArea`（子区） | 各港 VTS 区域（如「宁德VTS区域」）—— **分区与总区都要建**
`RadioCallingInPoint` | 各 VTS 报告线
`ShipReport` × N | 航行计划 / 终止 / 变化 / 其他（紧急异常、活动、引航报告）
`Applicability` × N | 见下方「Applicability 建与不建」判断规则
`Authority`、`ContactDetails`（eng+zho）、`ServiceHours` | 可复用
`WaterwayArea` | 航道/桥区水域，净空高填 `textContent`

`categoryOfVesselTrafficService` 多选：信息服务 / 交通组织服务 / 助航服务。
`serviceAccessProcedure` 填「应船舶请求可提供助航服务」这类服务获取说明。

### Applicability 建与不建（VTS 特有判断）

| 情况 | 做法 | 原因 |
|---|---|---|
| 文件用通用称谓（"客船""外国籍船舶""载运危险货物的船舶"） | **不建** Applicability，在记录表备注"系统内关联" | 这些是全局共用实体，系统中已有，无需每个数据集重复创建 |
| 文件**自行定义**船舶类别并给出具体判定标准（如天津案例"载运特殊危险货物船舶：1.100吨及以上爆炸品；2.X类散装化学品…"） | **必须建** Applicability，在 `information/text` 里放判定标准 | 这是本地新增类别，系统中没有对应实体 |
| 管理区有独特的适用条件（如"300总吨及以上的其他中国籍船舶（温州）"） | **建** Applicability，名称带地域后缀 | 虽然类似通用类别，但条件有地方特殊性 |

> 判断口诀：**如果去掉该条文的 Applicability 定义，读者仍能从通用知识理解"谁需要遵守" → 不建；否则必须建。**

### 多文件源处理

VTS 指南 + 定线制 + 报告制多份文件时（所有文件只生成一个 GML）：
- 每个要素的 `sourceIndication` 填**描述其地理位置/坐标的那份文件**
- 其他来源填进 `textContent/sourceIndication`
- `clause` 字段格式：`《文件简称》第X条`，如 `《管理细则》第三十一条`、`VTS指南 驶入报告`
- 范围相同的 VTSA 与 SRSA **各自关联对应来源的 ShipReport**

### ShipReport 分解规则（每种报告类型独立建一条）

| categoryOfShipReport | 对应内容 | 典型出处 |
|---|---|---|
| `sailing plan` | 驶入报告、开航报告、动态报告 | 船舶报告 第X条 |
| `final` | 抵达报告、最终报告 | 船舶报告 第X条 |
| `deviation` | 变化报告 | 船舶报告 第X条 |
| `other` | 引航报告、紧急异常报告、海洋污染物报告 | 引航 / 安全 条款 |

每条 ShipReport 的 textContent 结构：
```jsonc
{ "categoryOfText": "extract",
  "information": [
    { "headline": "Entry Report", "language": "eng",
      "text": ["WHEN: ...", "TO: ...\rVIA: ...\rGIVING: ..."] },
    { "headline": "进港报告", "language": "zho",
      "text": ["报告时机：...", "报告：...\r报告方式：...\r报告内容：..."] }
  ] }
```

### ENC 覆盖判断

引航员登离水域信息与 ENC 相同 → **不建** S-127 要素。
ENC 未提供详尽资料的航道（如三都澳主航道、漳湾航道白马大桥），
其通航信息可作为文本属性填进所在的 VTS 区域要素（总区 + 子区都填）。

## 3. 交通管理规定 / 船舶交通管理系统安全监督管理规则

**参照**：`127CN00TJHG000002.gml`（天津，最复杂）；指南 7.3
**命名**：`127CN00<地域>_VTSM` 或 `127CN00<地域>_SSSR001`

这类文件条文最多，是返工率最高的专题。做法：**先出要素清单表，再逐个编码。**

### 典型要素构成（天津案例节选）

| 地理要素类型 | 数量 | 出处特征 |
|---|---|---|
`VesselTrafficServiceArea` | 1 总区 + 6 分区 | 各分区名称带值守频道（如「天津VTS分区一VHF09」）
`RadioCallingInPoint` | 1 | 报告线（可从 ENC 导入，如 CN323001）
`RestrictedAreaNavigational` | 十余个 | 限速区、单向通航区、小船航道限制区、复式航道限制区
`UnderkeelClearanceAllowanceArea` | 十余个 | **按条件逐个建**，同一航道可有 1/2/3 号
| 信息要素类型 | 说明 |
`Authority` | 天津海事局
`ContactDetails` × 2 | 天津VTS中心（中/英）
`Applicability` | 载运特殊危险货物船舶、外国籍船舶、船长大于50米的中国籍船舶、拖带长度大于50米或宽度大于15米的中国籍船舶、小型船舶、渔业船舶
`ShipReport` × 4 | 航行计划报告、变化报告、抵达报告、其他报告
`Regulations` × 3+ | 航道通航及避让规则、复式航道水域航行规则、各航道及附近水域航行规则

### 要点

- 分区命名带频道，便于用户识别值守频道（如「天津VTS分区一VHF09」）
- 限速区按「主航道西侧 / 东侧 / 全段」分别建要素
- 富余水深：**同一航道不同条件建多个 UCAA**，各自关联对应 APPLIC 与许可类型
  （如「液化天然气船」`not required` / `required`）
- 「渔业船舶」在中心渔港航道 → `prohibited`
- 规则要素关联对应地理要素 + APPLIC（`included`）
- **所有 VTS 子分区共享同一套 ShipReport、ContactDetails、Authority 关联**——不要为每个分区
  创建独立的 ShipReport
- CautionArea（雷达盲区）只关联 Authority，**不关联所有船舶类型的 Applicability**

### 管制类条文（指南 6.5）

> 大沽沙航道 259 号灯浮标以西，实施船舶单向通航。
> 以东（10 万吨级航道）夜间实施单向通航，日间遇下列情况实施单向通航：1. 视程小于3000米；……

- 第一句（无条件）→ 建航行限制区，
  `textContent/information/text = ["Implement one-way traffic for vessels", "实施船舶单向通航"]`
- 其余条款（有条件）→ 建航行限制区 + 规则信息要素，二者关联；
  规则关联 APPLIC（`included`）：「船宽大于等于45米船舶」「载运特殊危险货物且船宽大于等于35米的船舶」
  「载运特殊危险货物的船舶」「液化天然气船舶」等
- 但**纯由指挥中心/VTS 研判下达的临时管制**（视程/风力/冰况/临时管制时）→ **不作表达**，见 07 号文档

## 4. 商渔船碰撞高风险警示区

**参照**：`127CN00TJHCRA01.gml`（天津）；指南 7.4
**命名**：`127CN00<地域>HCRA01` 或 `127CN00<地域>_PA001`

> ⚠️ `ConcentrationOfShippingHazardArea` 在 XSD 里**没有 `controlAuthority`**，
> 只能通过 `theRxN` 关联 Regulations（再由其 `theOrganisation` 指向 Authority）
> 或在系统内关联主管机构。

```jsonc
{ "ref": "hcra-1", "type": "ConcentrationOfShippingHazardArea",
  "featureName": { "eng": "...Concentration of Shipping Hazard Area", "zho": "曹妃甸东部水域商渔船碰撞高风险警示区" },
  "attributes": { "categoryOfConcentrationOfShippingHazardArea":
                  ["concentration of merchant shipping", "concentration of fishing vessels"] },
  "textContent": [ { "categoryOfText": "extract", "information": [ /* 商船、渔船航行建议 */ ] } ],
  "geometry": "g-1",
  "associations": [ { "role": "theRxN", "target": "rec-1" } ] }
```

**注意**（指南 7.4 原注）：商船、渔船航行建议本应建 `Recommendations` 信息要素关联各警示区，
但海事通 APP 目前无法接入信息要素 —— 为使 APP 中能显示航行建议，
**把内容填进警示区的文本属性**。

坐标附件常见 `area.csv`（列：no / name / y / x，度分秒用短横分隔）：

```bash
python scripts/coords.py --csv area.csv --group-col name --close
```

## 5. 沿海公共航路

**参照**：`127CN00DDPDLR1001.gml`（丹东港-大连航路一）；指南 7.5
**命名**：`127CN00<地域>_CPR001`

```jsonc
{ "ref": "rm-1", "type": "RouteingMeasure",
  "attributes": { "categoryOfRouteingMeasure": "recommended route" },
  "textContent": [ { "categoryOfText": "extract",
                     "information": [ { "text": { "eng": "Course 045°/225°…", "zho": "航向045°/225°…" } } ] } ],
  "associations": [ { "role": "permission", "target": "applic-fishing",
                      "permission": "not recommended" } ] }
  // RouteingMeasure 在 XSD 里没有 controlAuthority，主管机构靠 theRxN→Regulations 或系统内关联
```

要点：
- 必须关联 APPLIC「渔船」，关联关系 **`not recommended`（不推荐）**
- 航路相关的航行文字填航路要素的文本属性；**航向信息填 `information/text`**
- **二审完成后**还需在系统内编辑「所属海区」「航道类型」两个属性（GML 不承载）

## 6. 渔船推荐航路

**参照**：`127CN00TJFVRR001.gml`（天津海域）；指南 7.6
**命名**：`127CN00<地域>FVRR001`

与沿海公共航路配方相同，**唯一区别是关联关系为 `recommended`（推荐）**。

- `categoryOfRouteingMeasure = recommended route`
- 关联 APPLIC「渔船」，`permission = recommended`
- 航向信息填 `information/text`
- 航法、航行注意事项填进 `RouteingMeasure` 的文本属性，**不为它们单独建地理要素**
- 坐标附件常见 `XY.csv`（列：序号 / 航路名称 / Y / X，度分秒用空格分隔）：
  ```bash
  python scripts/coords.py --csv XY.csv --group-col 航路名称 --type curve
  ```

## 7. 桥区水域

**参照**：`127CN00XMBA002.gml`（厦门辖区桥梁）
**命名**：`127CN00<地域>BA00N`

- 桥区水域含**禁锚/限速/禁追越/禁掉头**等禁止/限制性规定时，每座桥建一个
  `RestrictedAreaNavigational`，用 `restriction` 枚举承载（「不得锚泊」→ `anchoring prohibited` 等）；
  仅净空高 / 禁止会遇等**无枚举需求**时用 `WaterwayArea`，净空信息填 `textContent`
- 无法用 `restriction` 枚举表达的桥区通航规定，原文摘录进 `textContent`（范围描述除外，见 01 §5）
- 桥区范围优先按来源文件；文件未给则查「海上交通安全管理条例」
  「桥区水域管理规定」「桥区水域通告」按条款勾绘；无坐标时几何留空、记录表注明「几何待人工录入」
- `Authority` 在系统内关联（记录表里标「Authority（系统关联）」）
- 桥梁净空信息需**同步更新**到智慧航保数字服务系统的通航要素

一份通告统一公布多座桥时，一个数据集内并列多个同类型要素，共用 `common.sourceIndication`。

### 条文批注范例（桥区水域管理办法）

来自厦门辖区桥梁等真实文件的条款批注，照此判定：

| 条款类型 | 判定 | 做法 |
|---|---|---|
| 普适性条款（进入前保持主机/舵/锚/导航设备良好；掌握水文气象、通航桥孔净空尺度；加强瞭望瞭头等） | 不摘录 | 属从业者常识，textContent 不予摘录 |
| 限速 / 最高航速 | 表达 | `RestrictedAreaNavigational` + `restriction = speed restricted`；限速值（如「12节」）进 `textContent`；找不到具体限速值则不录入 |
| 具体禁止行为（禁锚、禁追越、禁掉头、禁捕捞、禁过驳等） | 表达 | 逐项选对应 `restriction` 枚举（如「不得锚泊」→ `anchoring prohibited`）；只有无法枚举的内容才原文摘录进 `textContent` |
| 约束主体非船舶行驶行为（船舶所有人/经营人/管理人督促…；桥梁建设管理单位…） | 不表达 | 主体非船舶，S-127 不予表达 |
| 范围元数据（「桥区水域范围根据航道等级调整、代表船型变化…动态调整并公布」） | 不表达 | 属范围管理条款，「代表船型」非 S-127 表达范围 |

## 8. 船舶避险推荐水域

**参照**：`127CN00PTWRVEW001.gml`（平潭）；也是 `templates/featureset.example.json` 的原型
**命名**：`127CN00<地域>WRVEW001`

- 每片水域建一个 `PlaceOfRefuge`，`status = recommended`
- 停泊要求、注意事项填 `textContent`（分 headline 成组，中英成对）
- 关联 `Authority`（`controlAuthority`；PlaceOfRefuge 是有这个关联的 11 个要素类之一）
- 不具强制性 → 用 `status = recommended` 表达，不要用限制区

## 9. 其他地域性规定的归属（指南 7.7）

以下文字视作**地域性规定**，填进地理要素或信息要素的文本属性（而不是不表达）：

> - 「从事捕鱼的船舶，应避免在通航分道内捕捞，不应妨碍按通航分道行驶的任何船舶的通行。」
> - 「船舶不得在警戒区、通航分道及其端部的附近水域锚泊，紧急情况确需锚泊的应报告主管机关。」
> - 「船舶在追越时，应征得被追越船同意，并与之保持足够的横距。」

理由：《1972 国际海上避碰规则公约》允许捕鱼船进入通航分道、未规定追越横距、
未规定警戒区不得锚泊；《海上交通安全法》《水上交通管制管理办法》也不涉及；
《船舶交通管理系统安全监督管理规则》只规定了航道/港池/禁锚区不得锚泊。
—— 即这些是**本地新增要求**，对合规航行有实质影响，所以要表达。
