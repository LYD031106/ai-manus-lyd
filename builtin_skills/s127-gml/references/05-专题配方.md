# 专题配方

常见条文用途的选型规则。先核对本次原文，再按证据决定要素、字段和关联。示意结构只用于说明编码方式，字段值取自本次原文。

---

## 0. 要素清单推导原则（不预设数量）

> 本节只给**推导方法**，不给固定数字。数量、名称、分段一律以公告/附件为准。

1. **先枚举公告里的命名对象**：水域、桥梁、航段、掉头区、锚地、警戒区、报告类型、联系方式、适用船舶类别等。公告每命名一个，就先记一条候选。
2. **合并**：只有公告明确写“整体划定”“合并为一处”“为相邻桥梁整体划定”等，才把多个对象合并成一个要素；合并后名称用公告的整体名称。
3. **拆分**：公告分别命名的长航段、不同限速段、不同掉头区、不同报告类型，逐条建；不要因为“看起来是同一片水域”就合并。
4. **信息要素最小化**：Authority、Applicability、ShipReport、ContactDetails、Regulations、ServiceHours 只有在公告/本专题配方明确要求时才建；不要因为“规则上更完整”就额外增加。
5. **名称**：优先用公告/附件原名；附件名称已带海域/港口/航段的，直接照抄，不裁剪。
6. **几何类型**：完整边界或能从原文唯一推导的边界可建 `surface`。原文只定义中心线且要素类允许时用 `curve`。已经划定水域但无法确定其范围时，登记几何待补录。
7. **清单先定稿**：先输出一张“序号/要素类/数量/中英文名/几何类型/来源条款”表，再写 `featureset.json`；数量对不上时回公告核对，不套用固定数字。

## 1. 定线制和报告制

**指南**：7.1
**命名**：`127CN00<地域>_SRS_VTS001`

### 关键判断

先与最新 ENC 比对：**定线制内容通常已被 ENC 完全覆盖 → 不转换为 S-127 要素**。
只有当定线制文件包含 ENC 未表达的**航行规则条款**时，才按条款作用范围建
`RouteingMeasure`，把条款填进其文本属性或建 `Regulations` 关联。

### 要素配方

| 要素 | 说明 |
|---|---|
`ShipReportingServiceArea` | 报告制覆盖区，填 `requirementsForMaintenanceOfListeningWatch`
`ShipReport` × N | 按 `categoryOfShipReport` 分：航行计划报告 / 终止报告 / 变化报告 / 其他报告（含污染物报告）
`RadioCallingInPoint` × N | 各报告线；`communicationChannel` 填全部可用 VHF；`trafficFlow = two-way`；`componentOf` → SRSA
`Applicability` × N | 各类适用船舶（可复用，不填来源）
`Authority` | 主管机构（可复用）
`ContactDetails` × 2 | 交管中心，eng / zho 各一份
`ServiceHours` | 24小时值班（可复用）

### 关联

```
SRSA --permission(required)--> APPLIC（报告制适用船舶）
SRSA --permission(permitted)--> APPLIC（自愿加入的300总吨以下船舶）
SRSA --reptForTrafficServ--> ShipReport（各类型）
SRSA --consistsOf--> RadioCallingInPoint（自动补 componentOf）
SRSA --controlAuthority--> Authority
SRSA --theContactDetails--> ContactDetails
RadioCallingInPoint --permission(required)--> APPLIC（经过报告线须报告的船舶）
ShipReport --reportTo--> Authority（报告对象机构）
ShipReport --mustBeFiledBy(not required)--> APPLIC（免除报告的船舶）
```

## 2. VTS 服务指南

**指南**：7.2
**命名**：`127CN00<地域>VTS001`

### 要素配方

| 要素 | 说明 |
|---|---|
`VesselTrafficServiceArea`（总区） | 原文定义了总区且其范围能够独立核对时才建立
`VesselTrafficServiceArea`（子区） | 按原文明确的独立 VTS 分区建立；不要求固定层级
`RadioCallingInPoint` | 各 VTS 报告线
`ShipReport` × N | 航行计划 / 终止 / 变化 / 其他（紧急异常、活动、引航报告）
`Applicability` × N | 见下方「Applicability 建与不建」判断规则
`Authority`、`ContactDetails`（eng+zho）、`ServiceHours` | 可复用
`WaterwayArea` | 无可编码限制的普通航道；法规划定的桥区按 §7 选型

`categoryOfVesselTrafficService` 多选：信息服务 / 交通组织服务 / 助航服务。
`serviceAccessProcedure` 填「应船舶请求可提供助航服务」这类服务获取说明。

### Applicability 建与不建（VTS 特有判断）

| 情况 | 做法 | 原因 |
|---|---|---|
| 文件用通用称谓（"客船""外国籍船舶""载运危险货物的船舶"） | **不建** Applicability，在记录表备注"系统内关联" | 仅在已核实目标系统确有等同实体并允许引用时复用；需要独立交付时建立适用对象关系 |
| 文件**自行定义**船舶类别并给出具体判定标准（如按货物类别与证载吨位共同判定） | **必须建** Applicability，在 `information/text` 里放判定标准 | 这是本地新增类别，系统中没有对应实体 |
| 管理区有独特的适用条件（如船籍和吨位必须同时满足） | **建** Applicability，名称带地域后缀 | 虽然类似通用类别，但条件有地方特殊性 |

> 按原文判断适用对象是否是规则的一部分，不能用通用知识补充适用对象；只有已核对的等同实体才能复用。

### 多文件源处理

VTS 指南 + 定线制 + 报告制多份文件时（所有文件只生成一个 GML）：
- 每个要素的 `sourceIndication` 填**描述其地理位置/坐标的那份文件**
- 其他来源填进 `textContent/sourceIndication`
- `clause` 字段格式：`《文件简称》第X条`，如 `《管理细则》第三十一条`、`VTS指南 驶入报告`
- 范围相同的 VTSA 与 SRSA **各自关联对应来源的 ShipReport**

### ShipReport 分解规则（每种报告类型独立建一条）

| categoryOfShipReport | 对应内容 | 典型出处 |
|---|---|---|
| `sailing plan` | 驶入报告、开航报告、动态报告 | 船舶报告 第X条 |
| `final` | 抵达报告、最终报告 | 船舶报告 第X条 |
| `deviation` | 变化报告 | 船舶报告 第X条 |
| `other` | 引航报告、紧急异常报告、海洋污染物报告 | 引航 / 安全 条款 |

每条 ShipReport 的 textContent 结构：
```jsonc
{ "categoryOfText": "extract",
  "information": [
    { "headline": "Entry Report", "language": "eng",
      "text": ["WHEN: ...", "TO: ...\rVIA: ...\rGIVING: ..."] },
    { "headline": "进港报告", "language": "zho",
      "text": ["报告时机：...", "报告：...\r报告方式：...\r报告内容：..."] }
  ] }
```

### ENC 覆盖判断

引航员登离水域信息与 ENC 相同 → **不建** S-127 要素。
ENC 未提供详尽资料的航道（如三都澳主航道、漳湾航道白马大桥），
其通航信息可作为文本属性填进所在的 VTS 区域要素（总区 + 子区都填）。

## 3. 交通管理规定 / 船舶交通管理系统安全监督管理规则

**指南**：7.3
**命名**：`127CN00<地域>_VTSM` 或 `127CN00<地域>_SSSR001`

这类文件条文最多，是返工率最高的专题。做法：**先出要素清单表，再逐个编码。**

### 按条文决定要素

| 原文证据 | 表达 |
|---|---|
| 有明确的 VTS 服务范围或独立分区 | 分别建 VesselTrafficServiceArea，范围与频道按原文 |
| 公布独立报告线或报告点 | 各线、点独立建 RadioCallingInPoint，保持图元类型 |
| 区域确有航行限制 | 用 RestrictedAreaNavigational 并核对适用范围和例外 |
| 明确富余水深值或计算条件 | 用 UnderkeelClearanceAllowanceArea，分别关联有区别的适用对象 |
| 明确主管机关、联系语言或工作时间 | 只创建或复用本次确有的 Authority、ContactDetails、ServiceHours |
| 说明报告程序或规定法定义务 | 分清 ShipReport 与规则类信息；按真实条件建立适用对象关联 |

### 要点

- 以原文名称标识分区；频道写入目录允许的属性，原名含频道可保留
- 限速区按「主航道西侧 / 东侧 / 全段」分别建要素
- 富余水深：**同一航道不同条件建多个 UCAA**，各自关联对应 APPLIC 与许可类型
  （如「液化天然气船」`not required` / `required`）
- 只在原文明示时对特定船型使用 `prohibited`，并保留适用条件和范围
- 规则要素关联对应地理要素 + APPLIC（`included`）
- 报告程序、主管机关和联系信息确实一致时复用；原文区分不同分区时保留区别
- CautionArea（雷达盲区）只关联 Authority，**不关联所有船舶类型的 Applicability**

### 管制类条文（指南 6.5）

> 大沽沙航道 259 号灯浮标以西，实施船舶单向通航。
> 以东（10 万吨级航道）夜间实施单向通航，日间遇下列情况实施单向通航：1. 视程小于3000米；……

- 第一句（无条件）→ 建航行限制区，
  `textContent/information/text = ["Implement one-way traffic for vessels", "实施船舶单向通航"]`
- 其余条款（有条件）→ 建航行限制区 + 规则信息要素，二者关联；
  规则关联 APPLIC（`included`）：「船宽大于等于45米船舶」「载运特殊危险货物且船宽大于等于35米的船舶」
  「载运特殊危险货物的船舶」「液化天然气船舶」等
- 但**纯由指挥中心/VTS 研判下达的临时管制**（视程/风力/冰况/临时管制时）→ **不作表达**，见 07 号文档

## 4. 商渔船碰撞高风险警示区

**指南**：7.4
**命名**：`127CN00<地域>HCRA01` 或 `127CN00<地域>_PA001`

> ⚠️ `ConcentrationOfShippingHazardArea` 在 XSD 里**没有 `controlAuthority`**，
> 只能通过 `theRxN` 关联 Regulations（再由其 `theOrganisation` 指向 Authority）
> 或在系统内关联主管机构。

```jsonc
{ "ref": "hcra-1", "type": "ConcentrationOfShippingHazardArea",
  "featureName": { "eng": "...Concentration of Shipping Hazard Area", "zho": "曹妃甸东部水域商渔船碰撞高风险警示区" },
  "attributes": { "categoryOfConcentrationOfShippingHazardArea":
                  ["concentration of merchant shipping", "concentration of fishing vessels"] },
  "textContent": [ { "categoryOfText": "extract", "information": [ /* 商船、渔船航行建议 */ ] } ],
  "geometry": "g-1",
  "associations": [ { "role": "theRxN", "target": "rec-1" } ] }
```

**注意**（指南 7.4 原注）：商船、渔船航行建议本应建 `Recommendations` 信息要素关联各警示区，
但海事通 APP 目前无法接入信息要素 —— 为使 APP 中能显示航行建议，
**把内容填进警示区的文本属性**。

坐标附件常见 `area.csv`（列：no / name / y / x，度分秒用短横分隔）：

```bash
python scripts/coords.py --csv area.csv --group-col name --close
```

## 5. 沿海公共航路

**指南**：7.5
**命名**：`127CN00<地域>_CPR001`

```jsonc
{ "ref": "rm-1", "type": "RouteingMeasure",
  "attributes": { "categoryOfRouteingMeasure": "recommended route" },
  "textContent": [ { "categoryOfText": "extract",
                     "information": [ { "text": { "eng": "Course 045°/225°…", "zho": "航向045°/225°…" } } ] } ],
  "associations": [ { "role": "permission", "target": "applic-fishing",
                      "permission": "not recommended" } ] }
  // RouteingMeasure 在 XSD 里没有 controlAuthority，主管机构靠 theRxN→Regulations 或系统内关联
```

要点：
- 公告/配方要求时才关联 APPLIC「渔船」；关联关系按公告填 `not recommended` / `recommended`
- 航路相关的航行文字填航路要素的文本属性；**航向信息填 `information/text`**
- **几何类型**：按 §0。只有原文明确总宽度对称分布于中心线两侧时，才可各取总宽度的一半。
- **二审完成后**还需在系统内编辑「所属海区」「航道类型」两个属性（GML 不承载）

## 6. 渔船推荐航路

**指南**：7.6
**命名**：`127CN00<地域>FVRR001`

与沿海公共航路配方相同，**唯一区别是关联关系为 `recommended`（推荐）**。

- `categoryOfRouteingMeasure = recommended route`
- 公告/配方要求时才关联 APPLIC「渔船」，`permission` 按推荐/非推荐填写；公告没有要求就不建 Applicability
- 航向信息填 `information/text`
- 航法、航行注意事项填进 `RouteingMeasure` 的文本属性，**不为它们单独建地理要素**
- **几何类型**：按 §0 核对原文；航段宽度或偏移有变化时保留原文分段和各段参数。
- 坐标附件常见 `XY.csv`（列：序号 / 航路名称 / Y / X，度分秒用空格分隔）：
  ```bash
  # 只做坐标换算，不直接决定几何类型
  python scripts/coords.py --csv XY.csv --group-col 航路名称
  ```

## 7. 桥区水域

**命名**：`127CN00<地域>BA00N`

- 国内海事法规划定的桥区水域统一建 `RestrictedAreaNavigational`。按原文桥名命名，
  不拼接原文未使用的地名前缀。桥梁信息通告的 `textContent/information` 只保留净空高。
- 桥区范围以法规附件、核实的海图或用户提供的准确 GML 为准；找不到准确几何时进入补录流程。
- `Authority` 在系统内关联。桥梁净空信息同步到智慧航保数字服务系统的通航要素。

一份通告统一公布多座桥时，一个数据集内并列多个同类型要素，共用 `common.sourceIndication`。

### 按条文区分桥区与通航孔

- 核对通告是否明确引用桥区管理办法，再逐条确定限制的范围、对象和例外。地名与桥名分别核对；不能用某桥的参数或规则填写另一座桥。
- 同一桥有通航孔和通航孔外安全水域时按原文分别建面。追越与并列行驶均禁止才使用 30，单纯禁止追越使用 28。只有明确禁入才用 7；限制进入用 8。不能根据「桥区」二字推断任一限制码。
- 安全水域的缓冲距离、边界、分段数均以公告和准确几何为准。多个同名独立分区使用同一 partitionGroup；不是每座桥都需要同样数量的面。明确通航尺度不等于明确横向边界。
- 普通航段有实际航行限制时使用 RestrictedAreaNavigational；原文明确定线制、推荐航路、深水航路等才使用 RouteingMeasure，并编码原文类型。目录不支持的限制放入条文，除非交付方明确确认兼容码。
- 报告义务以规则、适用对象和确切地理范围表达。报告服务与规定义务分别建模。报告线、报告点不混用；灯标和岸线无法定位时保留待补。
- 已在 ENC 等同表达的锚地可省略；有独立限制时从原文提取。圆形边界采用原文圆心和半径；原始少顶点边界保留。

## 9. 其他地域性规定的归属（指南 7.7）

以下文字视作**地域性规定**，填进地理要素或信息要素的文本属性（而不是不表达）：

> - 「从事捕鱼的船舶，应避免在通航分道内捕捞，不应妨碍按通航分道行驶的任何船舶的通行。」
> - 「船舶不得在警戒区、通航分道及其端部的附近水域锚泊，紧急情况确需锚泊的应报告主管机关。」
> - 「船舶在追越时，应征得被追越船同意，并与之保持足够的横距。」

理由：《1972 国际海上避碰规则公约》允许捕鱼船进入通航分道、未规定追越横距、
未规定警戒区不得锚泊；《海上交通安全法》《水上交通管制管理办法》也不涉及；
《船舶交通管理系统安全监督管理规则》只规定了航道/港池/禁锚区不得锚泊。
—— 即这些是**本地新增要求**，对合规航行有实质影响，所以要表达。

## 10. 内河航道通航安全管理规定

**指南**：7.3 扩展
**命名**：`127CN00<运河/航道简称>00N`

此类文件通常为「正文（按章节的航行规则条文）+ 附件目录」，附件目录给出
警戒区、掉头区/应急停泊区、弯曲航段的上下界坐标点（常见句式：
「以地理坐标点 X 向航道方向作垂直延长线」）。附件给出独立法定范围及用途时才据此创建要素，
正文条文按作用范围落成要素、文本或信息要素。

### 要素配方

| 要素 | 数量 | 出处特征 |
|---|---|---|
| `RestrictedAreaNavigational` | N | 限速区、弯曲航段、掉头区、待闸锚地、禁鸣区、禁止行为水域 |
| `CautionArea` | N | 附件「航行警戒区目录」，每个警戒区一个 |
| `UnderkeelClearanceAllowanceArea` | N | 富余水深条文，**按条件各建一个** |
| `WaterwayArea` | N | 前后船安全距离、避让规则（按枢纽上/下游分片） |
| `Regulations` | N | 按规则主题拆分（警戒区规定 / 引航规定 / 禁止行为…） |
| `Applicability` | N | 船舶尺度用 `vesselsMeasurements` 结构化编码 |
| `Authority` | N | 按原文适用范围关联主管机构；代表同一机构的对象可复用 |

### 各模式编码细则

**限速区**（如「XX至XX水域航速不得超过每小时 15 公里」）：

```jsonc
{ "type": "RestrictedAreaNavigational",
  "featureName": { "eng": "Waters Between Boundary A and Boundary B",
                   "zho": "甲界至乙界水域" },
  "attributes": { "restriction": "speed restricted" },
  "textContent": [ { "categoryOfText": "abstract or summary",
                     "information": [
                       { "headline": "Article 14", "language": "eng",
                         "text": ["The navigation speed shall not exceed 15 kilometres per hour."] },
                       { "headline": "第十四条", "language": "zho",
                         "text": ["航速不得超过每小时15公里。"] } ] } ],
  "associations": [ { "role": "controlAuthority", "target": "auth-1" } ] }
```

原文或经核实的几何支持将限速水域分成独立航段时，可为每段建立独立 Surface，名称按来源填写。

**弯曲航段**（附件「弯曲航段目录」）：命名 `No.N Curved Fairway Section` /
`N号弯曲航段`；原文对该弯道限速时填 `speed restricted`，textContent 引用限速条款。
另有弯道航行要求时，按实际内容另记对应条款。

**掉头区**（附件「掉头区和应急停泊区目录」）：命名 `XX River Mouth Turning Area` /
`XX河口掉头区`；限制的是**船型**而非禁止掉头 —— 用 `permission` 关联允许船型的
Applicability（如「船长小于 90 米的船舶」）；「兼做应急停泊区」写入 textContent；
**不填** `restriction`。

**待闸锚地**（如「XX枢纽船闸上游待闸锚地」）：命名 `Upstream/Downstream Approach
Anchorage,XX Hub` / `XX船闸上游/下游待闸锚地`；锚地水域限速建
`RestrictedAreaNavigational`，`restriction = speed restricted`，textContent 用
`categoryOfText = "extract"`（可不带 headline）填限速值。

**禁鸣区**（如「每日 22 时至次日 6 时禁止鸣放声号」）：命名用起止地物
（以本次原文为准）；`restriction` 不填；
textContent 填禁鸣时段，headline 引用条款号。

**航道全域要求**（AIS/VHF 值守等）：按航段建 `XX Canal` / `XX Canal Fairway`
`RestrictedAreaNavigational`，可 `theRxN` 关联多条 Regulations。

**富余水深**：`underkeelAllowance` 填数值与取值方式；不同条件各建一个，
几何可相同：

```jsonc
{ "type": "UnderkeelClearanceAllowanceArea",
  "featureName": { "eng": "Canal Underkeel Clearance Area Example",
                   "zho": "运河富余水深示意区" },
  "attributes": { "underkeelAllowance": { "underkeelAllowanceFixed": 0.7,
                                          "operation": "smallest value" } } }
```

危险货物等附加条件另建一个（如 0.8 米），`permission` 关联对应 Applicability。

**安全距离 / 避让规则**（如「与前船安全距离不得少于 2 倍本船船长」）：
建 `WaterwayArea`，`dynamicResource = "static"`；textContent 可含多条 information
（安全距离 + 避让规则），各自带 headline：

```jsonc
{ "type": "WaterwayArea",
  "featureName": { "eng": "Upstream Waters of the Hub",
                   "zho": "枢纽上游水域" },
  "attributes": { "dynamicResource": "static" },
  "textContent": [ { "categoryOfText": "extract",
                     "information": [
                       { "headline": "Article 15", "language": "eng",
                         "text": ["The safe distance from the preceding vessel shall not be less than twice the length of the own vessel (not applicable to the waters of navigation structures)."] },
                       { "headline": "第十五条", "language": "zho",
                         "text": ["与前船安全距离不得少于2倍本船船长（不适用于通航建筑物水域）。"] },
                       { "headline": "Article 19", "language": "eng",
                         "text": ["Upbound vessels shall give way to downbound vessels."] },
                       { "headline": "第十九条", "language": "zho",
                         "text": ["上行船舶应当避让下行船舶。"] } ] } ],
  "associations": [ { "role": "controlAuthority", "target": "auth-1" } ] }
```

**警戒区**（附件「航行警戒区目录」）：每个警戒区一个 `CautionArea`，命名
`Precautionary Area No.N` / `N号航行警戒区`；`theRxN` 关联「航行警戒区规定」
Regulations；**不填** textContent / restriction，也不直接 controlAuthority。
「船长超过 90 米的船舶进入警戒区前应主动告知…」这类**有条件条文**建
Regulations（双语命名 + textContent 摘录 + headline 条款号），
`isApplicableTo` 关联适用船型。

**Applicability 船舶尺度**：能给出尺度的船型用 `vesselsMeasurements` 结构化编码：

```jsonc
{ "type": "Applicability",
  "featureName": { "eng": "Vessels with a length of over 90 meters",
                   "zho": "船长超过90米的船舶" },
  "attributes": { "vesselsMeasurements": { "comparisonOperator": "greater than",
                                           "vesselsCharacteristics": "length overall",
                                           "vesselsCharacteristicsValue": 90,
                                           "vesselsCharacteristicsUnit": "metre" } } }
```

无尺度可填的类别（外国籍船舶、载运散装液体危险货物的船舶）只填双语名称。

### 关联模式

```
CautionArea --theRxN--> Regulations（警戒区规定）
Regulations --isApplicableTo--> Applicability（>90m 船舶）
掉头区/限船型限制区 --permission--> Applicability（允许船型）
UCAA（附加条件） --permission--> Applicability（危险货物船舶等）
航道全域要素 --theRxN--> Regulations（禁止行为/引航规定…）
其余地理要素 --controlAuthority--> Authority
```

### 常见遗漏（自查）

- 限速水域是否分段、弯曲航段是否限速，以条款和附件所记的适用范围为准。
- 掉头条款先辨别行为禁令和船舶适用条件，再编码实际限制。
- 检查附件是否新增正文未逐一列名的独立要素，并保留各项来源。
- 富余水深的计算方式、数值及适用船舶分别按对应条款结构化。
- 名称采用原文。没有独立名称时，按原文的地物和要素用途写出可追溯的名称。
