## 一、不表达清单（指南 3.2、6.2）

以下内容**不转换为 S-127**。判断错了就是白做，而且会污染数据集。

| # | 内容 | 依据 |
|---|---|---|
| 1 | 海上从业者应掌握的**常规性/常识性内容** | 指南 3.2(4)：着重表达直接影响船舶合规航行的信息 |
| 2 | 「禁止船舶在水下管线两侧保护水域范围内锚泊或拖锚航行」等《海底电缆管道保护规定》相关条文 | 指南 6.2(1)，视作从业者常识 |
| 3 | **海上作业申报**规定 | 指南 6.2(2)，不属于 S-127 表达域（与船舶航行/通航规则无关） |
| 4 | 海上航行、**入港申请**等申报的规则条文 | 指南 6.2(3)，行为主体是船公司/代理而非船舶 |
| 5 | 由指挥中心/VTS 基于观测研判、通过 VHF 通知执行的**临时交通管制**条件 | 指南 6.2(4)，属交通管理要求而非船舶应遵守的航规 |
| 6 | 无线电、雷达等**通信设施的覆盖范围** | 指南第 2 章 |
| 7 | ENC 已表达同等内容的部分 | 指南 3.2(2) |
| 8 | 被新文件完全取代的旧文件内容 | 指南 3.2(1) |
| 9 | 桥区水域范围调整、**代表船型**变化等范围元数据（「桥区水域范围根据航道等级调整、代表船型变化…动态调整并公布」） | 「代表船型」不属于 S-127 表达范围；范围管理条款不作文本属性提取 |

### 混合条文的取舍

逐句区分作业申请、临时指挥与直接影响船舶航行的要求。同条同时存在明确的航行规则或独立报告程序时，按其实际范围、时机和对象编码。由指挥中心临时研判并另行发布的措施按指南排除；已公布并直接适用于船舶的固定或条件性规则按原文保留。地域性新增要求按 [专题配方 §9](05-专题配方.md) 核对上位规则和适用条件。

## 二、已知返工点

从真实审核记录（`gml校对` / `gml审核` 工作表的「修改意见」列）归纳：

| 返工点 | 正确做法 |
|---|---|
| 要素名称过长 | 优先使用原文正式名称；需缩短时保留能定位要素及区分范围的部分 |
| 给 `ShipReport` 挂 `controlAuthority` / `permission` | XSD 里没有这两个角色；用 `reportTo` / `mustBeFiledBy` |
| 给 `RouteingMeasure`、`UCAA`、`ConcentrationOfShippingHazardArea` 挂 `controlAuthority` | XSD 里没有；靠 `theRxN`→Regulations→`theOrganisation` 或系统内关联 |
| 属性名写成 `radioCommunications` | XSD 里是小写 c：`radiocommunications` |
| 英文名与系统内既有要素不一致 | 与系统保持一致；同一实体不要出现两种英译 |
| `source` 英译与文号不对应 | 核对中英文名称指向同一发文机构、文号和时间 |
| 桥区范围画错 | 按实际适用的条款、附图或核实的海图补录；只有名称或条件不足时登记几何待补 |
| 遗漏系统内同名要素的净高信息 | 核实是否为同一要素并按目标系统流程补录净空，标记重复项待核对 |
| `text` 里带了条款序号 | 去掉，序号只进记录表 |
| 中英文不成对 | `featureName`、`information` 必须成对 |
| 可复用要素填了来源 | Authority / ContactDetails / ServiceHours / APPLIC 不填 `sourceIndication` |
| 报告类型选成 与实际目的不符 | 根据报告目的、报告内容和适用程序选目录类别，保留触发位置 |
| 富余水深只建一个要素 | 不同条件必须分别建 UCAA |
| 沿海公共航路漏编两个属性 | 二审后补「所属海区」「航道类型」 |
| 禁止锚泊只写进 textContent 而未用 `restriction` | 「不得锚泊」→ `RestrictedAreaNavigational` + `restriction = anchoring prohibited`（`RestrictedAreaRegulatory` 无此值） |
| 「不得锚泊」带「除…外」例外被判成 `anchoring restricted` | 明确的通常禁令保留 `anchoring prohibited`，并记录紧急、维护等例外；只在特定对象或时段生效时保留限定条件 |

## 三、交付前自检

### A. 机器可查（跑脚本）

回归自检（改过脚本后跑一次，确认没把保真度弄坏）：

```bash
python scripts/roundtrip_check.py '示例/**/*.gml'    # 非预期差异应为 0
```


```bash
python scripts/validate_featureset.py featureset.json     # ERROR 必须为 0
python scripts/build_gml.py featureset.json -o out.gml --assoc-csv 关联补录清单.csv
python -c "import xml.etree.ElementTree as ET; ET.parse('out.gml'); print('well-formed OK')"
```

**ERROR（违反 `schemas/S127.xsd`，必须修）**：要素类不存在；该要素类没有这个子元素
（会提示最接近的正确名，如 `radioCommunications` → `radiocommunications`）；
缺少 `minOccurs>=1` 的必填项；超出 `maxOccurs`；枚举 label 不在 XSD 列表；
几何种类与 XSD 几何类型不符（如给 `GM_Surface` 要素塞了线）；
关联目标不存在，或 `permission`/`controlAuthority` 等指向了错误的要素类；
坐标越界；数据集命名违规；日期格式错或起止颠倒；单段 `text` 超 300 字符。

**WARN（指南约定或需人工确认）**：中英未成对；`displayName` 约定；可复用要素填了来源；
专属要素缺来源；条款序号残留；命中不表达清单关键词；经纬度疑似写反；
`text` 总长超 300；未关联 Authority（且该要素类有 `controlAuthority`）；
许可/包含类型未指定；APPLIC 的 `logicalConnectives` 与条件数不匹配；
Regulations/Restrictions 与发文层级不匹配。

> **不会因为「某个可选属性没填」而报错。** XSD 里 `minOccurs=0` 的元素一律不强制 ——
> 原文有就填，没有就不填。要素类的必填项清单见 `02-要素字典.md` §二。

### B. 人工核对（脚本查不了）

**属性**
- [ ] 中英文内容**语义一致**（不只是都非空）
- [ ] 英译使用海事、航海专业英语；中文括号已转英文括号
- [ ] 从 PDF 复制的文本已清理多余空格、半拼字符
- [ ] 要素名称精简，体现所属区域/系统 + 功能；词首大写；数值带千分位
- [ ] `reportedDate` 取自文件实际发布日期，无法确认时省略；文号或日期缺件说明单列
- [ ] `source` 优先用文号，且已查过《现行有效规范性文件目录》
- [ ] `sourceType` 与发文机构层级匹配（直属海事局及以上 = law or regulation）
- [ ] `Regulations` / `Restrictions` 的选用与机构层级匹配

**内容判断**
- [ ] 逐条过了「不表达清单」
- [ ] 与最新 ENC 比对过，ENC 已表达的没有重复转换
- [ ] 描述地理范围的文字一律未进 `text`（范围只通过 geometry 表达；无坐标的几何留空并在记录表注明「几何待人工录入」）
- [ ] 只与单一地理要素相关的条文，没有多余地建信息要素
- [ ] 需特定条件才成立的规则，建的是信息要素而非地理要素

**要素清单与公告逐条核对**
- [ ] 公告每命名一个水域/桥梁/航段/掉头区/锚地/警戒区/报告类型，清单里都有对应项；没有多建
- [ ] 公告明确“整体划定/合并为一处”的才合并；公告分别命名的长航段、多桥、多报告类型没有自行合并
- [ ] 公告没有区分的对象，没有自行拆分
- [ ] 名称来自公告/附件，带所属海域/港口/航路段，没有被裁剪
- [ ] 公告/配方没有要求的信息要素（Authority/Applicability/ShipReport/ContactDetails/Regulations/ServiceHours）没有额外增加
- [ ] 航路几何与原文所定的中心线或边界一致；从宽度推导边界时核对偏移方向、分段和适用范围。
- [ ] 数量对不上时已回公告核对，没有套用固定数字

**关联**
- [ ] 有 `controlAuthority` 的要素类都关联了唯一 Authority；
      没有该关联的要素类（RouteingMeasure、UCAA、CSHA、RadioCallingInPoint…）
      已确认主管机构的间接来源（聚合/规则/系统内关联）
- [ ] 每条 `permission` / `isApplicableTo` / `theApplicableRxN` 都写了类型
- [ ] 报告线关联了要求报告的 APPLIC
- [ ] SRSA/VTSA 与报告线**各自**关联了 APPLIC
- [ ] 检查了三方关联关系，去掉了冗余关联
- [ ] 总区和分区各自已按原文定义和实际适用范围关联

**几何**
- [ ] 坐标与原文/附件逐点核对过
- [ ] 同名补录边界已和独立原文或海图锚点核对；无可靠锚点的项已标明核对范围。
- [ ] 引用文件的适用范围和效力已核实；尚未解决的原文依据列进 `sourceReview`，产物保持草稿状态。
- [ ] 几何清单逐个列出名称、缺失或待确认状态，以及需要补录的关联；草稿和最终 GML 采用不同文件名
- [ ] 草稿地理要素缺几何时按允许的几何类型标注 `nilReason="unknown"`；信息要素不写几何属性。最终文件有缺失时应阻止交付为成品。
- [ ] 同名分段只使用经确认的对应，不能按 FIN、行号或顶点数量分配。按原文拆分的通航孔和安全水域要有各自独立的边界。
- [ ] 按公开断面切分、按完全重合共边拼接、或根据海图勾绘的几何均注明依据和待复核状态；几何脚本的输出不是复核通过的结论
- [ ] 桥区按限制区编码；复核通航孔及安全水域分别建面、枚举及项目兼容项
- [ ] 最终 GML 检查报告分列目录/结构错误、编码告警和人工核对项；完整 XSD 缺失时标明未执行
- [ ] 面要素环闭合、无自相交

## 四、生产数据中常见的复核项

- 核对文件名、datasetFileIdentifier 与 datasetTitle 是否共同标识本次交付。生成新数据集时检查命名和标识重复，续编按交付要求保留获准的标识。
- 核对单段文本长度、语言和角色基数。确有多个主管范围时按定义分别建立要素或选择目录允许的关联，不能把多个单值角色塞进一个要素。
- 必填字段的取值无据时按 DCEG 缺值规则填写 `{"$nil": true}` 并记录出处或待补项；报告线遇到多个真实服务归属时核对版本允许的角色及基数。

## 五、记录表

```bash
python scripts/make_record_table.py featureset.json -o S-127要素生产与检查记录表.xlsx
```

生成三个工作表：`文件解析` / `gml校对` / `gml审核`，统一按以下八列输出，每个要素一行：

| 要素类 | FIN | 中文名称 | 英文名称 | 编码信息 | 有效期起 | 有效期止 | 来源 |
|---|---|---|---|---|---|---|---|

脚本自动填入本次构建采用的要素名称、FIN、属性编码、有效期和来源。
条款出处在要素清单里填写 `"clause": "附件1 二（三）"`，与关联及关联类型一同保存到 Excel 的「来源」格批注；
审核意见也追加到批注，不增加主表列。CSV 通过配套的 `featureset.json`、`evidence.json` 追溯条款及证据。
完整格式及字段规则见 [09-UML结构与文本抽取规则.md §8.5](09-UML结构与文本抽取规则.md#85-结果表格)。

每轮审核后把意见落实回要素清单 JSON，
重新跑一遍 validate → build，保证 JSON、GML、系统三者一致。
